# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Pubsplash is an accessibility-first Windows streaming client for Audio Pub (an Icecast-based livestreaming platform, server source: github.com/the-byte-bender/audiopub-sv), built with wxDragon (wxWidgets bindings). Its users are primarily screen-reader users; every control must be Tab-reachable and properly announced. The full product spec is in `project2.md` (`project.md` is an earlier draft of the same spec).

## Commands

- Build: `cargo build` (first build compiles wxWidgets via CMake/Ninja and takes several minutes; later builds are fast)
- Test: `cargo test`
- Single test: `cargo test <name_substring>`
- Ignored tests (hit the real audiopub.site or play audio): `cargo test <name> -- --include-ignored`. Notable: `real_login_bad_credentials` (live server), `sapi_speaks` (audible), `sapi_synthesizes_pcm`
- Run: `./target/debug/pubsplash.exe` (release builds hide the console via `windows_subsystem`)

Per `agents.md`: every change set must update `changelog.md` (bulleted entries under `## Unreleased` → `### Additions`/`### Fixes`/`### Changes`) and keep `README.md` accurate (especially the shortcut table).

## Architecture

Three long-lived domains connected by channels; the UI never blocks on audio or network:

1. **UI (main thread)** — `src/ui/`. wxdragon main loop. A 100 ms `Timer` ("the pump", in `ui/mod.rs::pump_events`) drains `NetEvent`/`EngineEvent` receivers into UI state; once a second it refreshes durations and chat relative times. `App` (an `Rc` holding `RefCell`s) is the shared UI-side state: persisted `Config`, transient `Runtime`, handles to the engine/net/speaker threads, and `Widgets` (populated after `ui::build`).
2. **Audio engine (thread)** — `src/audio/`. `engine_loop` mixes 10 ms blocks: per-source WASAPI capture threads push f32 into rtrb rings → per-source `ChannelStrip` (volume + 50 ms mute fades) → master strip → optional LAME MP3 encode → tokio mpsc to the Icecast sender. Sources that aren't OS-captured (TTS, sound events) are `FeedKind::External`: the engine parks an rtrb producer in `ExternalFeeds` keyed by source name, and other subsystems push samples via `ExternalFeeds::push` (retry on `Full`, abort on `Gone`).
3. **Network (tokio on a background thread)** — `src/net/`. `net_loop` owns the `AudioPubClient` (reqwest + cookie store) and, while streaming, two tasks: the Icecast source connection (hand-rolled `PUT` over `TcpStream` in `icecast.rs`) and the SSE consumer (`sse.rs` parser over `/live/{id}/events`).

TTS (`src/tts/`) is nine engines behind one router. `speaker::Speaker` holds two `tts::queue::Queue`s — bounded and **drop-oldest**, so a chat flood loses the stale messages, not the fresh ones — and dispatches on the engine id:

- **SAPI** (`tts/sapi.rs`) keeps its own COM STA thread owning `ISpVoice`. Each message is spoken locally (async) and, when `output_to_stream`, synthesized to memory at 48 kHz stereo and fed to `ExternalFeeds`. This thread's ownership rules are load-bearing; don't move work onto it.
- **Every other engine** (`tts/engines/*.rs`) implements `engine::SpeechEngine` — one method, text in, interleaved stereo f32 at `SAMPLE_RATE` out — and runs on the `tts-net` worker, which owns a current-thread tokio runtime (`tts/net.rs::block_on`). These have no local voice: `ExternalFeeds` is their only output, so `output_to_stream` is applied in `ui/mod.rs::sync_engine_sources` by dropping the strip's `to_master`, and the user monitors the strip (CTRL+M) to hear them.

Adding an engine is a file under `tts/engines/`, a row in `engines::ALL`, and an arm in `engines::build`. Engine ids are stable `&'static str` constants decoupled from display names, and `resolve_id` falls back to SAPI for anything unknown — nothing else in the app hard-codes an engine name. Credentials live in one global `SpeechConfig` (DPAPI-encrypted via `secret::Secret`), never per-source. Every API is asked for PCM or WAV at a rate we choose; only Google Translate and Star need `tts/decode.rs` (symphonia). Failures become `TtsError`, are rate-limited to one a minute per message by `speaker::Problems`, and surface in the chat list from the pump — never a modal, which would fire per chat message.

`Config` (in `config.rs`) is both the persisted settings file and the scene/source model; `state.rs` adds list-manipulation methods (`switch_to`, `delete_scene`, `move_up`...) that return `ListEdit::Changed/Unchanged` so the UI knows whether to refresh/save. After any scene/source edit, call the chain in `ui/scenes.rs::after_scene_edit` (save → refresh scenes list → `on_sources_changed` → `refresh_app_processes` + `sync_engine_sources` + `rebuild_mixer` → refresh sources list, which must come last so it reads the re-resolved app cache).

Everything a user sees or hears a source called comes from `src/source_name.rs`, never from `SourceConfig.name` — that field is an identity key (it routes `ExternalFeeds` and TTS `SpeakRequest`s) and is always just the kind's display name plus a counter, since there is no rename UI. `list_labels` is the verbose Scenes-list form, `strip_labels` the concise mixer form; both dedupe within a scene. They read a `NameContext` (capture devices + resolved Application processes) built from `App::name_context`. Application sources resolve to a running process via `audio::device::resolve_apps`, cached in `Runtime.apps` and refreshed every 2 s by the pump; when a pid changes the pump re-syncs the engine, and when a name changes it calls `home::relabel_source_strips`, which re-labels strips **in place** (a `rebuild_mixer` would move focus).

## Hard-won protocol facts (verified against the real server; do not "simplify" these away)

- The server kills any live source that isn't **MP3 or AAC** (it ffprobes the mount). MP3 via LAME is the default; the spec's mention of Opus is unimplementable.
- SvelteKit form actions (`/login`, `/live/new`) return **200 + JSON envelope** (`{"type":"redirect"|"failure",...}`) to non-browser clients, not a real 303. Parse the envelope (`audiopub.rs::action_result`), never trust the HTTP status alone.
- Chat SSE user objects contain **both `name` and `displayName`** — they must be separate serde fields (an alias makes serde reject the payload as a duplicate field, silently dropping every message).
- `__data.json` responses use SvelteKit's devalue flat-array encoding, and multiple nodes can carry a `user` object; only the stream-instructions page node has `streamKey` — skip non-matching nodes, don't bail.
- Connecting to the SSE endpoint counts as a listener; subtract 1 for display.
- Desktop Audio capture uses **process-exclusion loopback** (`new_application_loopback_client(std::process::id(), false)`) so Pubsplash's own output (TTS, cues) can never loop into the stream. Don't switch it back to plain render-device loopback.

## wxDragon notes

- Widget handles are `Copy`-like and cheap to clone into event closures; state lives in `Rc<App>` captured by clone.
- Screen readers do not announce adjacent `StaticText` labels or even some controls' own labels. Use `ui/mod.rs::set_accessible_name` (a name-only MSAA `AccessibleImpl`) on any new slider, checkbox, list, or text input — and re-set it when the meaning changes (see the send-level slider re-label in `sends.rs`). The crate's `set_accessibility_label` is macOS-only; don't use it. **Never use `set_accessible_name` on a `ListBox`** — lists go through `ui/native_acc.rs::install` instead, and that file documents why at length. The short version: wx's `WM_GETOBJECT` handler calls `GetOrCreateAccessible()`, so *every* MSW control is wrapped in a `wxWindowAccessible` whether or not we install one; it answers a list's name with `wxWindow::GetName()` (the literal `"listBox"`) and its child count with the number of child *windows* (zero), and forwards everything it declines to a **second, unrelated** object from `CreateStdAccessibleObject` whose child ids index list *items*. A screen reader reconciling a row across those two graphs announces it twice on every tab or F6 into the list. `native_acc` answers `WM_GETOBJECT` from a subclass proc ahead of wx and returns `DefWindowProcW`, so the list is a plain Win32 control again and takes its name from the `StaticText` in front of it — which every list must therefore keep. That same proc also raises the caret row's `EVENT_OBJECT_FOCUS` on `WM_SETFOCUS`, before wx dispatches its focus events: Windows raises one focus event for the list and the list box raises another for the row, NVDA's queue keeps only the last per window *if they arrive together*, and wx's focus dispatch in between was splitting them — which is what made every list read its row twice. Don't add work to a list's `wxEVT_SET_FOCUS` path expecting it to be free. **Radio boxes go through `native_acc::install_radio_box`** for the same reason: a `wxRadioBox` is a group box whose items are real `wxRadioButton` *windows*, so wx wraps every one of them and answers their names with `wxWindow::GetName()` — the literal `"radioButton"` for each item and `"radioBox"` for the group — leaving the items effectively unnamed. `set_accessible_name` can't reach them (it would replace the group's accessible only, and wxdragon hands out no handles for the children), so `install_radio_box` subclasses the group's HWND and every child `BUTTON` and lets OLEACC build the native objects, which take their names from the controls' own text. `set_accessible_name` stays correct for controls with no MSAA children (sliders, checkboxes, buttons, text fields).
- NVDA announces a `ListBox` with zero items as "Unknown". Every list that can empty therefore keeps a placeholder row (`"No chats"`, `"No sources"`...) — see `ui/list.rs`, and use `list::fill` to populate. That row is not data: widget indices reach a config collection only through `list::selection(list, len)`, which rejects it (several call sites would otherwise `Vec::remove` past the end). `bus_list` is the exception, with its own pinned `MASTER_ROWS` mapper. The placeholder is announced because the row exists — it must never be selected, and `list::fill` never touches the selection at all. A screen reader speaks a row as it becomes selected, so a list that reselects while refreshing talks over what the user is doing, and these lists refresh constantly (the Sources list on every arrow key in the Scenes list, and again every two seconds by the app poll). Selection moves belong only to deliberate edits. The Home tab's stream overview is a list for the same reason: it was a read-only `TextCtrl` rewritten every second to keep its duration current, and `set_value` resets the caret, so arrow keys never reached the end. `home::refresh_overview` is a hand-rolled `list::sync` because of one extra rule — `set_string` on MSW deletes and reinserts the row, and the rule it adds is this: **`set_string` on the *selected* row is announced whether or not the list has focus; on any other row it is silent.** So the once-a-second refresh never writes the selected row, whichever row it is, and nothing in the list can speak on its own. Do not "improve" this into a focus test — gating on focus instead of selection means the tick rewrites the selected row the whole time the user stands on some other control, and NVDA reads the duration out every second. Currency comes from the two events that precede a read instead: `on_selection_changed` (the row just vacated updates at once, so stepping off Duration and back reads the current time) and `on_set_focus`, the one caller that passes `Selected::Write`. That callback nesting is why nothing in `refresh` may hold a `run` borrow across a `set_string`/`set_selection`. Its rows are addressed by `OverviewRow` kind, not index, since which rows exist depends on stream/record state; `ShownStreamUi.overview` caches what is really in the widget, and skipping the Duration write deliberately leaves that cache stale so the row is retried next tick. So main-window lists refresh through `list::sync`, which relabels in place or does nothing at all when the rows already match and only reports `Synced::Rebuilt` when the selection is genuinely gone — refreshes fan out (`after_scene_edit` refreshes the Scenes list on every *source* edit, `add_plugin` refreshes the bus list), and rebuilding an unchanged list is what makes a screen reader announce it.
- Keyboard shortcuts are mostly mnemonics in labels (`"S&witch to scene"` = ALT+W). The context-aware stream button relies on this: `&Start streaming` (ALT+S) vs `S&top streaming` (ALT+T). Mnemonics are **dialog-wide**, not per notebook page — `::IsDialogMessage` searches the whole dialog, so a new button on any Preferences tab must dodge the letters every other tab claims.
- **User keybinds** (`keybind.rs` = data + catalogue, `ui/keybinds.rs` = runtime, `ui/keybinds_ui.rs` = the Preferences tab and its dialog) do not use an accelerator table — there is none in the app — but ride the one `WH_KEYBOARD_LL` hook in `ui/help.rs`, which is also the only way capture can see ESC/arrows/CTRL+letter (`IsDialogMessage` eats them in pre-processing). The arm order in `help::keyboard_hook` is load-bearing: capture, then F1, then F6, then dispatch, so the two built-ins can never be shadowed — which is why `keybinds_ui` refuses F1 and F6 as bindings. Chords are Windows VK codes, never wx key codes. The hook touches only atomics and a snapshot refreshed by `keybinds::reload`; every action runs from `keybinds::pump` on the UI thread. Non-global bindings require `foreground_is_main_frame`, which is what keeps them from firing under our own modal dialogs while the pump timer keeps ticking.
- Key events: match through `ui/mod.rs::key_of` (returns `(key_code, ctrl_down)`); call `event.skip(true)` on unhandled keys or the control goes dead.
- A **CTRL+letter** shortcut needs one thing more than `skip(false)`, or Windows plays the default error sound alongside it. CTRL+letter is a control character (CTRL+M is 0x0D), so `TranslateMessage` posts a `WM_CHAR` for it regardless of what the key-down handler did; that char re-enters `wxWindowMSW::MSWProcessMessage`, whose navigation block only inspects `WM_KEYDOWN`, and falls through to `::IsDialogMessage` on the parent panel, which treats it as an unmatched mnemonic and beeps — all during pre-processing, before dispatch, where no wx handler can intervene. The control has to claim `DLGC_WANTCHARS` from `WM_GETDLGCODE`; sliders do, in `ui/slider_uia.rs`'s subclass proc, which is what makes CTRL+M on a mixer strip quiet. Anything else needs its own. Do not reach for `wxWANTS_CHARS`/`DLGC_WANTALLKEYS`: wx reads those as implying `DLGC_WANTTAB` (`window.cpp`'s `MSWProcessMessage`), which hands TAB to the control and traps focus.
- **Every `Slider` needs `ui/slider_uia.rs`**, without exception: `slider_uia::install` for the value and an `on_key_down` driving `slider_uia::key_step` for the movement keys. `set_accessible_name` alone is not enough — it only answers MSAA, while NVDA reads UIA and gets the native trackbar's percentage-of-range, and the native trackbar's arrow and page keys run backwards (Up and Page Up move *down*). Keep the returned `SliderAnnouncer` alive for the slider's lifetime and `uninstall()` it before the window is destroyed; the provider registry is keyed by HWND. `key_step` maps Home to the maximum and End to the minimum — the inverse of both the native mapping and the usual convention, but every slider in the app agrees, which is what matters. `home.rs` and `fx_params.rs` predate `key_step` and inline their own mappings (one interleaves CTRL+M, the other steps in floats); new sliders use the helper.
- Dialog outcome constants are `ID_OK`/`ID_YES`/`ID_CANCEL`; modal dialogs need explicit `.destroy()` after `show_modal()`.
- The mixer is rebuilt (not patched) on any source change — `rebuild_mixer` destroys and recreates an inner panel so creation order = Tab order.
- The frame `on_close` handler vetoes via `WindowEventData::General(e).veto()` when the user declines the streaming-exit confirmation.

## Buses, sends, and VST FX (implemented)

- **Routing** lives in `config.rs`: global `BusesConfig` (buses + `master_chain`), per-source `sends: Vec<SendConfig>` (bus by *name*) and `to_master`. Bus list edits are on `Config` (in `state.rs`) because rename/delete rewrites sends. `Config::fix_up_routing` (called in `load_from`) drops dangling sends.
- **Engine graph** (`audio/mod.rs::mix_one_block`): source strip → (if `to_master`) master, plus post-fader per-send `ChannelStrip` into each bus buffer; each bus runs its `FxChain` → bus strip → master; then the master `FxChain` → master strip. Buses/sources are addressed **by index**; sends carry a `bus_index` resolved from names in `ui/mod.rs::sync_engine_sources`. Denormals are flushed (FTZ/DAZ) at the top of `engine_loop`.
- **Plugin hosting is in-process**, both formats. `vst/host2.rs` hosts VST2 (full `AEffect`, editor, chunks) — distinct from the scan-only `vst/vst2.rs` that compiles into `pubsplash-scan.exe`; `vst/host3.rs` hosts VST3 on the `vst3-host` crate. `vst/instance.rs` is the seam: `PluginInstance` is the format enum, and `PluginInstance::process` is the **only** place that knows which format it is holding — it returns a `Processed`, never a bool, so a chain cannot leave its output unwritten and promote the previous plugin's block. `PluginInstance` is deliberately not `Clone` and holds each plugin **by value**, not behind an inner Arc: every owner reaches a plugin through one `Arc<PluginInstance>`, so the retirement path below is the only way to the last reference.
- **Threading contract** (headers at the top of `host2.rs` and `host3.rs`, enforced by structure): `load`/`Drop`/dispatcher/editor on the **UI thread**; `process_replacing` / `process_stereo` on the **engine thread**. Parameter accessors are UI-thread-only — VST2 tolerates either thread, but VST3's `IEditController` is main-thread-only, so the intersection is what callers must obey. `Vst2Plugin` is `unsafe Send+Sync` on that basis; `Vst3Plugin` gets both from the compiler (a `Mutex<Vst3Inner>` around a `Send` plugin) with no `unsafe impl` at all.
- **Nothing blocks the engine, in either format.** `Vst3Plugin::process_stereo` and `Vst2Plugin::process_replacing` both take their mutex with `try_lock` and report `Processed::Passthrough` if they can't have it. UI operations that hold it for longer than a block (editor open/close, chunks/`save_state`, the parameter-list refresh, and `Drop`) raise the shared `vst/suspend.rs` `SuspendFlag` and sleep `SETTLE` (60 ms) *before* locking; the engine sees the flag, keeps processing, and reports `Processed::Retiring`. Short dispatches (parameter names, `effEditIdle`) take the lock without the settle — they run on a timer. VST2's `get_parameter`/`set_parameter` stay outside the lock entirely, per the format's contract and because `snapshot` reads them with the plugin already held. `FxChain` carries a per-unit wet/dry gain ramped over `FADE_SECONDS`, so a plugin leaves and rejoins the signal path as a 50 ms crossfade rather than a hard switch — which also covers bypass. Poisoning is always recovered (`unwrap_or_else(|e| e.into_inner())`): a `None` from `snapshot()` means "keep what config already has", never "write zeros".
- **Layouts.** VST3 negotiates mono or stereo in *and* out (`host3.rs::negotiate_layout`); mono output is mirrored to both channels and mono input is fed `(L+R)/2` in both formats. A plugin with **no audio input bus** — an instrument or other generator — is allowed, and `PluginInstance::mix_mode` reports `MixMode::Add` for it so `FxChain` sums its output into the bus instead of replacing it. There is no MIDI plumbing: instruments are driven from their own interface. Wider-than-stereo output is still refused, with a message naming the channel count.
- **Ownership**: `App.fx` (`FxRuntime`) holds one `Arc<PluginInstance>` per live instance, kept index-aligned with `config.buses`. The engine holds clones inside `FxChain`s. **Plugin teardown must happen on the UI thread, with nothing borrowed**, and there are two halves to that:
  - the engine hands every chain it replaces back down a retirement channel (`park_chains`, used by both the `Shutdown` arm and the idle-park exit) and sends `EngineEvent::BusesApplied`; the pump then calls `AudioEngine::reclaim_retired_chains`. Never let the engine drop the last reference — every exit from `engine_loop` parks its chains first.
  - the UI's own reference goes to `App.orphaned_plugins` via `fx::orphan`, drained by the pump through `fx::release_orphans`. Dropping one inline would run teardown *inside* an `app.fx` borrow, and plugin teardown commonly pumps the Windows message queue and re-enters the UI.
  All chain lifecycle goes through `ui/fx.rs`. Chain edits send only the chain they touched (`sync_engine_chain`), and the engine carries surviving units' fade state across a replacement by `Arc::ptr_eq` (`FxChain::adopt_fades_from`) so an unrelated plugin mid-fade is not snapped to its endpoint.
- **Plugin DLLs are never unloaded, and neither are their factories.** `vst/module_pin.rs` takes one permanent extra `LoadLibraryExW` reference per distinct plugin binary before the first instance is created, and (`pin_factory`, after the first successful load) one permanent `IPluginFactory` reference. The second matters because `vst3-host` treats the factory as a local in `PluginImpl::load` and releases it once it has the component: a **shell** module — one DLL publishing many plugins, e.g. `WaveShell1-VST3` with 232 audio classes — keeps its per-process registry on the factory, and releasing it left `IComponent::terminate()` walking a torn-down table and dereferencing `-1`. `Vst2Plugin::drop`'s `FreeLibrary` and `vst3-host`'s (which has no per-module refcount and also calls `ExitDll`) then balance their own loads against that floor and can never unmap the image — which is what a plugin with a worker thread, timer, or COM stub still running does not survive. Instance identity is `vst::instance::next_effect_id`, a counter, **not** an address: an address is reused the moment the plugin is freed, and editors and `audioMasterSizeWindow` requests are matched by it.
- **A hard crash is not a panic.** A faulting plugin kills the process with `STATUS_ACCESS_VIOLATION` — no unwind, no panic hook, no backtrace. `src/crash.rs` installs a top-level exception filter that logs the faulting address's **module and offset** (which names the plugin) and writes a minidump to `%LOCALAPPDATA%\pubsplash\crashes\`; `Vst2Plugin::drop`/`Vst3Plugin::drop` log breadcrumbs around each teardown step, and `logging.rs` pins the `vst3_host` target to debug so the crate's own module-cleanup lines survive. When investigating a crash, the last log line before the fault is the evidence.
- **Known `vst3-host` 0.7 gaps** (documented in `host3.rs`, not worked around): `restartComponent` is a crate stub, so the parameter list is re-read at point of use rather than on notification; `IEditController::getState` and `IPlugView::onSize` have no wrappers, so editor-side state does not persist and a self-resizing editor may be clipped.
- **Chain library** (`fx.rs`): named chains in `fx_chains.json`, `.pubfx` export/import, and `resolve_chain` (drives the missing-plugin dialog). `PluginRef::resolve` matches by unique_id/class_id, then path, then name.
- **Accessible params** (`ui/fx_params.rs`): OSARA-style dialog behind the testable `ParamSource` trait (`step_param`, `filter_params`, `formatted_value`). Announces via `set_accessible_name_value` (re-set on every change) plus a read-only value TextCtrl fallback.
- **Native editor** (`ui/fx_editor.rs`): plugin editor embedded in a wx `Frame` panel via `get_handle()` HWND; a `WH_KEYBOARD_LL` hook (installed only while editors are open) turns **F6** into "refocus the toolbar" so keyboard focus is never trapped. `editor_idle` and `audioMasterSizeWindow` are serviced from the 100 ms pump. Structural chain edits call `fx_editor::close_all` first (editor slot indices would go stale).
